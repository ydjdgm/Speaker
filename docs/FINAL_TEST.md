# Speaker 최종 사용자 시험

이 문서는 하나의 통합 시험 절차다. 위에서 아래 순서대로 진행한다. 개발 중 앱 실행·자동 테스트·실제 장치 시험은 수행하지 않았으므로 아래 결과는 아직 미검증이다. 각 단계의 결과를 **통과 / 실패 / 장비 없음**으로 기록한다. 실패 시 화면의 오류 문구와 `설정 및 진단`의 형식·지연·오버런·언더런을 기록한다.

## 1. 실행과 최초 설정

1. `C:\Users\tonyt\Documents\GitHub\Speaker\dist\Speaker\Speaker.exe`를 일반 권한으로 실행한다. 다른 PC로 복사할 때는 `Speaker-1.0.0-windows-x64.zip` 전체를 풀고 그 안의 `Speaker.exe`를 실행한다. DLL·platforms·translations 폴더를 함께 유지한다.
2. 최초 `VB-CABLE 연결 안내`를 읽고 닫는다. 시작 시 `전송 ON → 가상 마이크`, `프로그램 공유 ON`, `내 목소리 듣기 ON`, `녹음 ON → WAV 파일`이 모두 해제되어 있어야 한다.
3. USB 마이크와 Bluetooth 이어폰을 연결한다. `장치 / 프로그램 새로 고침`을 누르고 마이크에는 USB 마이크, 이어폰에는 실제 Bluetooth 출력 장치를 선택한다. Bluetooth 내장 마이크를 고르지 않는다.
4. VB-CABLE이 없다면 `설정 및 진단 → 가상 마이크 연결 안내 → 공식 VB-CABLE 사이트 열기`에서 공식 Windows 드라이버 ZIP을 받는다. 압축을 풀고 x64 설치 프로그램을 관리자 권한으로 실행하여 설치하고 재부팅한다. 이는 외부 드라이버의 필수 권한 승인 단계다. 재실행 후 새로 고침하고 `CABLE Input`을 선택한다. 드라이버가 없는 동안에도 전송을 제외한 모니터링·녹음은 사용할 수 있어야 한다.
5. 마이크와 프로그램을 모두 선택 해제한 상태에서 전송과 녹음을 각각 켜 본다. 두 동작 모두 OFF로 돌아오고 활성 소스가 없다는 설명이 나와야 한다. 이후 USB 마이크를 다시 선택한다.
6. 앱을 한 번 더 실행한다. 두 번째 믹서가 열리지 않고 이미 실행 중이라는 안내가 나와야 한다. Tab/Shift+Tab, 방향키, Space로 장치 선택·스위치·음량을 조절한다. Windows 배율 150%에서도 스크롤해 모든 조작에 접근할 수 있어야 한다.

## 2. 마이크 전송과 프로그램 격리

1. Discord의 입력을 **CABLE Output**, 출력을 **실제 이어폰**으로 정한다. Windows 기본 입력·출력은 변경하지 않는다. 테스트 통화 상대에게 다음 확인을 부탁한다.
2. Speaker에서 마이크 전달 음량 100%, `마이크 전달 음소거` 해제, `전송 ON → 가상 마이크`를 켠다. `전송 중` 상태와 입력 레벨이 표시되고 상대에게 목소리가 들려야 한다. 음소거를 켜면 목소리가 멈추고 해제하면 다시 들려야 한다.
3. Edge에서 유튜브 음악을 재생한다. 새로 고침 후 공유 프로그램에서 `msedge`를 선택하고 `프로그램 공유 ON`을 켠다. 별도 Chrome 또는 음악 플레이어에서 다른 소리를 재생한다. 상대는 목소리와 Edge 음악만 들어야 한다. 선택하지 않은 앱 소리는 들어가면 안 된다.
4. 같은 Edge의 다른 탭에서 소리를 재생하면 함께 공유될 수 있다. 탭·프로필·창 단위 격리는 지원하지 않는다. 통화는 Edge와 분리된 Discord 앱을 사용한다.
5. 프로그램 공유를 끄면 목소리만, 마이크 음소거만 켜면 Edge 소리만 전달되어야 한다. 두 음량을 각각 50%와 100%로 바꾸어 해당 소스만 바뀌는지 확인한다. 0%에서는 그 소스가 무음이어야 한다.
6. 공유 ON 상태에서 마이크를 `선택 안 함`으로 바꾸면 프로그램만 전송할 수 있어야 한다. 다시 USB 마이크를 선택한다. 이어폰·마이크 목록에는 VB-CABLE 입력이 나오지 않아야 한다. Speaker 자신은 공유 대상에 나오지 않아야 한다.
7. 음악이 끊기거나 줄어들면 Discord의 노이즈 억제·자동 입력 감도·자동 음량 처리를 해제한 뒤 비교한다. 이 처리는 Speaker 녹음 이후 통화 앱이 적용하므로 차이를 기록한다.

## 3. 독립 모니터링과 게임

1. 마이크를 선택한 채 `내 목소리 듣기 ON`을 켠다. 이어폰에 목소리가 한 번 추가되고 Edge 음악이 이 기능 때문에 중복 재생되지 않아야 한다.
2. 마이크 전달 음소거를 켜거나 전달 음량을 0%로 내려도 자신의 모니터링 목소리는 유지되어야 한다. `듣기 음량`을 30%와 100%로 바꿔도 상대가 듣는 전달 음량은 바뀌면 안 된다.
3. 전송을 끄고 모니터링만 남겨도 자신의 목소리는 들려야 한다. 모니터링을 끄면 그 목소리만 사라져야 한다. Bluetooth 지연을 적고, 유선 장치가 있는 경우에만 같은 조작을 비교한다.
4. 사용하는 게임에서 입력을 CABLE Output, 출력을 실제 이어폰으로 선택한다. 전송을 켜고 목소리·Edge 음악 전달, 마이크 음소거, 프로그램 공유 OFF를 반복한다. 게임에서도 해당 소스만 켜지고 꺼져야 한다.

## 4. 독립 녹음과 파일 확인

1. 전송을 끈다. USB 마이크 음소거 해제·전달 음량 100%로 둔다. `녹음 ON → WAV 파일`을 켜고 “첫 구간, 목소리만”이라고 말한다.
2. 5초 뒤 Edge 공유를 켜고 “두 번째 구간, 음악과 목소리”라고 말한다. 5초 뒤 공유를 끄고 “세 번째 구간, 목소리만”이라고 말한다. 도중에 모니터링을 켰다가 끈다.
3. 녹음을 끈다. `녹음 저장 완료`와 약 15초 이상의 시간이 보여야 한다. `녹음 목록`에서 파일명·날짜·길이·크기·저장됨 상태를 확인한다. 파일명은 `Speaker_날짜_시각.wav` 형식이다.
4. 해당 파일의 `탐색기에서 보기`로 파일이 선택되고, `저장 폴더 열기`로 현재 저장 폴더가 열려야 한다. 공유 및 전송을 끈 상태에서 탐색기에서 WAV를 기존 플레이어로 연다. 말한 세 구간과 Edge 공유 변화가 녹음에 반영되고 모니터링 조작 자체는 녹음에 영향을 주지 않아야 한다. 마이크가 모노라면 양쪽 채널에 목소리가 들려야 한다.
5. 플레이어를 닫는다. 이름 변경에 `CON`, `bad:name`을 입력하면 오류가 나고, `최종시험_첫녹음`은 `.wav` 파일로 변경되어야 한다. 다른 녹음과 동일한 이름으로 바꾸려 하면 충돌을 알려야 한다.
6. `휴지통으로 삭제`에서 `아니요`를 선택하면 파일이 남고, 다시 눌러 `예`를 선택하면 휴지통으로 이동해야 한다. 휴지통에서 해당 이름을 확인한다. 휴지통을 지원하지 않는 저장소에서 실패하면 오류만 표시해야 하며 영구 삭제되면 안 된다.

## 5. 저장 위치·파일 잠금·외부 변경

1. `저장 위치 변경`에서 문서 폴더 아래 `Speaker Final Test` 폴더를 만들고 선택한다. 녹음을 10초 만들어 정지한다. 새 녹음은 새 폴더에 생기고, 이전 녹음은 원래 폴더에 남아 양쪽이 목록에 표시되어야 한다.
2. 녹음 중 저장 위치를 기존 음악 폴더로 바꾼 뒤 정지한다. 진행 중이던 파일은 시작 당시 폴더에 남고 다음 녹음부터 변경한 폴더에 저장되어야 한다. 녹음 중 파일을 이름 변경·삭제하려 하면 막아야 한다.
3. 파일 잠금 오류는 일반 PowerShell에서 아래 명령을 실행한다. 나타나는 파일 선택창에서 방금 만든 WAV를 선택한다. 이 창을 유지한 채 Speaker에서 그 파일의 이름 변경·삭제를 시도하면 오류가 나야 한다. PowerShell에서 Enter를 눌러 잠금을 풀고 다시 시도하면 성공해야 한다.

   ```powershell
   Add-Type -AssemblyName System.Windows.Forms
   $dialog = New-Object System.Windows.Forms.OpenFileDialog
   $dialog.Filter = 'Speaker recording (*.wav)|*.wav'
   if ($dialog.ShowDialog() -eq 'OK') {
     $heldFile = [IO.File]::Open($dialog.FileName, 'Open', 'Read', 'None')
     try { Read-Host 'Try rename/delete in Speaker, then press Enter to unlock' }
     finally { $heldFile.Dispose() }
   }
   $dialog.Dispose()
   ```

4. 다른 시험 녹음 하나를 탐색기에서 다른 폴더로 옮긴다. 최대 3초 후 목록에 `찾을 수 없음`이 표시되어야 한다. `없는 항목 정리`를 누르면 목록에서만 제거되고 옮긴 파일은 남아 있어야 한다.

## 6. 장치·프로그램 오류 격리

1. 마이크+Edge 공유, 전송, 녹음, 모니터링을 모두 켠다. Edge를 완전히 종료한다(백그라운드 실행이 남는 경우 작업 관리자에서 Edge 프로세스도 종료). 프로그램 종료 안내와 공유 OFF가 나타나고, 마이크 전달·모니터링·녹음은 계속되어야 한다.
2. Edge를 다시 실행해도 자동 공유되면 안 된다. 새로 고침 후 다시 선택하고 공유를 직접 켠다.
3. USB 마이크를 분리한다. 마이크 오류와 모니터링 OFF가 나타나고, Edge 전송·녹음은 유지되어야 한다. USB를 다시 꽂아도 자동 캡처로 돌아가지 않아야 한다. 새로 고침·마이크 재선택·모니터링 ON으로 복구한다.
4. Bluetooth 이어폰을 끄거나 연결 해제한다. 모니터링 관련 오류가 나타나고 로컬 녹음과 가상 마이크 전달은 유지되어야 한다. 이어폰을 재연결하고 새로 고침·재선택·모니터링 ON으로 복구한다.
5. `설정 → 시스템 → 소리 → 더 많은 소리 설정 → 재생`에서 CABLE Input을 일시적으로 사용 안 함으로 바꾼다. 전송 오류와 OFF가 나타나되 녹음·모니터링은 유지되어야 한다. CABLE Input을 다시 사용하도록 바꾸고 새로 고침·재선택 후 전송을 직접 켠다.
6. 모든 소스가 사라져도 이미 진행 중인 녹음은 사용자가 끄기 전까지 남은 입력 또는 무음을 기록해야 한다. 오류 로그는 `%LOCALAPPDATA%\SpeakerLocal\Speaker\audio-errors.log`에 오류·장치 상태만 기록하며 오디오 내용을 포함하지 않아야 한다.

## 7. 저장 불가와 녹음 중 쓰기 실패

1. 녹음을 끈 상태에서 `저장 위치 변경`에 `C:\Windows\System32\config`를 입력한다. 폴더 선택 자체가 거부되면 권한 오류가 확인된 것이다. 선택이 가능한 경우 일반 권한 Speaker에서 녹음을 켜면 생성 실패가 표시되고 녹음은 OFF여야 한다. 이후 저장 위치를 음악 폴더의 `Speaker Recordings`로 되돌린다.
2. 녹음 도중 디스크가 가득 차는 상황은 실제 디스크를 채우지 않고 64 MB 시험용 가상 디스크로 재현한다. **관리자 PowerShell**에서 다음을 실행한다. 관리자 승인은 가상 디스크 연결에 필요하다. 스크립트는 새 시험 VHD만 만들며 기존 물리 디스크를 선택·포맷하지 않는다.

   ```powershell
   & 'C:\Users\tonyt\Documents\GitHub\Speaker\scripts\create-test-volume.ps1' -Create
   ```

3. Speaker 저장 위치를 `%LOCALAPPDATA%\SpeakerFinalTestVolume\Mount\Recordings`로 정한다(폴더 선택창 주소 칸에 붙여 넣기). 마이크·Edge 전송과 모니터링을 켜고 녹음을 시작한다. 최대 7분 기다리면 작은 가상 디스크가 가득 차 녹음만 OFF가 되고 저장 오류가 표시되어야 한다. 전송·모니터링은 계속되어야 한다. `.part` 및 `.journal` 복구 파일은 보존되어야 한다.
4. 저장 위치를 원래 음악 폴더로 되돌리고 10초 녹음·정지를 확인한다. 오류가 해제되고 새 녹음이 저장되어야 한다. 시험 VHD의 파일은 그대로 두고 관리자 PowerShell에서 아래 명령으로 분리한다. 원본 VHD는 삭제하지 않는다.

   ```powershell
   & 'C:\Users\tonyt\Documents\GitHub\Speaker\scripts\create-test-volume.ps1' -Detach
   ```

## 8. 장시간·분할·정상 종료·비정상 복구

1. 실제 저장 장치에 여유 공간 3 GB 이상을 확보한다. USB 마이크+Edge 공유, 전송, 녹음을 30분 이상 유지한다. 창을 최소화해도 계속되어야 한다. 1분·10분·30분의 진단 지연·오버런·언더런을 적는다. 지연과 큐가 계속 늘거나 소리가 반복해서 끊기면 실패로 기록한다. 시작/장치 변경 때의 일시적 누락과 지속 증가를 구분한다.
2. 별도 연속 녹음을 **3시간 1분 이상** 진행한다. 2시간 59분 50초부터 시간을 읽으며 경계를 지난 뒤 정지한다. 첫 파일은 정확히 3시간(2,073,600,044 바이트), 다음 파일은 나머지 구간이어야 한다. 두 파일의 끝과 시작을 외부 플레이어로 확인해 분할 때문에 단어나 음악 구간이 빠지지 않는지 확인한다.
3. 녹음·전송·내 목소리 듣기를 켜고 X를 누른다. 창만 숨겨지고 세 기능은 15초 이상 계속되어야 한다. 작업 표시줄 숨겨진 아이콘(∧)의 Speaker를 클릭하거나 우클릭 → `Speaker 열기`로 복원한다. 녹음 시간이 계속 증가하고 설정이 유지되어야 한다. 다시 X로 숨기고 트레이 우클릭 → `완전히 종료`를 선택한다. `아니요`면 기능이 유지되고, 다시 종료하여 `예`면 프로세스와 트레이 아이콘이 사라지고 WAV가 재생 가능해야 한다. 재실행 시 네 기능은 OFF이며 장치·음량·저장 폴더는 기억해야 한다. 창 상단 `앱 → 완전히 종료`도 같은 종료 동작인지 확인한다. 트레이가 없는 환경에서는 X가 최소화되어 작업 표시줄로 복원 가능해야 한다.
4. **새 시험 녹음**을 시작하고 “비정상 종료 복구 시험”이라고 말한 뒤 10초 이상 기다린다. 작업 관리자에서 Speaker의 `작업 끝내기`로 강제 종료한다. 같은 실행 파일을 다시 열면 복구 결과와 손실 가능성 안내가 나와야 한다.
5. `_복구.wav`가 목록에 나타나 재생 가능하고, 원래 `.part`와 `.journal` 파일은 삭제되지 않아야 한다. 마지막 순간의 일부 손실은 가능하다. 복구할 수 없는 파일은 성공으로 표시하지 않고 `복구 필요` 또는 오류 결과를 표시해야 한다. 재실행만으로 전송·공유가 켜지면 실패다.
6. `설정 및 진단`에서 `안정성 우선`을 켠 뒤 1분간 반복 확인한다. 형식과 버퍼 표시가 바뀌며 지연이 늘 수 있다. 기본 모드와 안정성 모드 결과를 각각 기록한다.

## 최종 성공 기준과 한계

선택하지 않은 프로그램이 전달되지 않고, 세 기능을 독립적으로 제어하며, WAV 저장·관리·복구가 위 기대 결과와 일치하면 기능 시험 통과다. 내부 지연 20 ms 이하는 설계 목표이며 보장치가 아니다. Bluetooth 종단 지연, DRM/캡처 제한, 통화 앱의 후속 처리, 장시간 드라이버 안정성은 이 시험에서 별도로 판단한다. 특정 게임 또는 장비가 없으면 그 항목을 통과로 간주하지 말고 미검증으로 남긴다.
